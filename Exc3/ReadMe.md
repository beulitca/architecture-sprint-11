## Q1 — Дизайн
Выбираем стек Lakehouse (S3/MinIO + Iceberg + каталог метаданных + Trino/Dremio + Airflow + Kafka/Debezium), поднимаем DEV, настраиваем SSO (Keycloak), базовые роли и маскирование, определяем границы доменов и черновики data contracts, собираем каркас портала самообслуживания. Фиксируем заморозку новых ETL в легаси-DWH.  
Принятие архитектурные решений в начале проекта

## Q2 — Пилоты и расширение
Подключаем ключевые источники (CDC из банка; batch HR/Inventory; API фарма/электроника), включаем каталог/линейность и DQ-ворота, публикуем первые доменные продукты (**Fintech**, **Medical Admin** без PHI), запускаем **Portal v1** с доверенными датасетами, начинаем бэкфилл тяжёлых отчётов из DWH.  
Демонстрация ценности бизнесу, обратная связь от доменов

## Q3 — Масштабирование и миграция
Перевести пилот в устойчивую эксплуатацию и расширить охват доменов на основе полученного опыта эксплуатации  
Масштабируем стриминг (Camel), при необходимости добавляем быстрые витрины для интерактивной аналитики; усиливаем доступ (RLS/CLS, маскирование), обновляем **data contracts до v1**. Публикуем домены **HR**, **Inventory**, **Financial Reporting**. Переносим потоки со старой инфраструктуры, начинаем выводить PowerBuilder.  

## Q4 — Промышленная эксплуатация и де-комиссия легаси
Минимизация легаси, предсказуемые SLA/SLO. 
Финализация доменных продуктов; формализуем SLO и инцидент-плейбуки; проходим комплаенс, тесты DR/BCP; **де-комиссия** большей части DWH-ETL/отчётов (оставляем лишь доменно оправданное).
